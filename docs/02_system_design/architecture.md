# 系统架构设计

## 1. 总体设计思路

系统按照职责分层，分为以下五层：

1. **支撑层**：统一定义所有 ROS2 消息、服务、动作，提供硬件驱动和公共工具库（`src/support/`）
2. **功能层**：传感器数据预处理、特征提取、算法推理（`src/function/`）
3. **决策层**：行为决策、任务规划、状态机管理（`src/decision/`）
4. **执行层**：运动控制、机构执行、安全门控（`src/execution/`）
5. **应用层**：系统启动编排、实时可视化、实验工具（`src/application/`）

## 2. 模块划分

```
┌─────────────────────────────────────────────────────────────┐
│               src/application/ (应用层 — 启动/可视化)         │
└─────────────────────────────────────────────────────────────┘
          │              │              │
┌─────────▼──────┐ ┌─────▼───────┐ ┌───▼──────────┐
│ src/execution/ │ │src/decision/│ │src/function/ │
│  (执行/控制层)  │ │  (决策层)   │ │  (功能/算法层)│
└────────────────┘ └─────────────┘ └──────────────┘
          │              │              │
┌─────────────────────────────────────────────────────────────┐
│                 src/support/ (支撑层 — 接口/驱动/工具)         │
└─────────────────────────────────────────────────────────────┘
```

## 3. Topic / Message 设计

| Topic | 消息类型 | Publisher | Subscriber | 频率(Hz) |
|-------|---------|-----------|------------|---------|
| `/sensor/raw` | `SensorData` | 功能层采集节点 | 功能层处理节点 | 100 |
| `/sensor/processed` | `SensorData` | 功能层处理节点 | 决策层节点 | 100 |
| `/result/decision` | `DecisionResult` | 决策层节点 | 执行层节点 | 10 |
| `/command/control` | `ControlCommand` | 执行层节点 | — | 10 |
| `/system/status` | `SystemStatus` | — | — | 1 |

> **注意**：此表为模板，请根据实际项目修改。

## 4. 节点数据流

```
[功能层] 采集/处理节点
    → /sensor/raw → /sensor/processed

[决策层] 决策节点
    → /result/decision

[执行层] 安全门控节点（可选）
    → /command/safe

[执行层] 控制节点
    → /command/control
```

## 5. 参数管理策略

- 所有可调参数存放在各包 `config/*.yaml` 中
- 全局共享参数存放在 `configs/` 顶层目录
- Launch 文件通过 `parameters` 字段加载 YAML 参数
- 禁止在 Python/C++ 代码中硬编码关键参数

## 6. QoS 策略

| 数据类型 | Reliability | Durability | 说明 |
|---------|------------|------------|------|
| 传感器数据 | BestEffort | Volatile | 高频，允许丢包 |
| 控制命令 | Reliable | Volatile | 关键，不允许丢包 |
| 状态信息 | Reliable | TransientLocal | 新订阅者可收到最新值 |
